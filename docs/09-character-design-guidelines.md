# キャラクターデザイン方針

## 目的

NanbyoData における疾患キャラクターは、疾患を覚えやすくし、カテゴリごとの世界観を持たせるための補助表現として扱う。  
医療情報そのものが主役であり、キャラクターは理解と記憶を助ける役割に留める。

## 基本原則

- 疾患の症状や苦痛を、そのままキャラクターの見た目にしない
- 病態を弱さ、欠損、変形として表現しない
- 当事者が見て不快になりにくい、穏やかで尊重のあるデザインを優先する
- キャラクターは「情報の入口」であり、疾患の軽視や玩具化にならないようにする

## カテゴリ設計

- まずカテゴリごとにテーマを定める
- そのカテゴリの中で、ベースとなる生き物やモチーフを **5種** 決める
- 同カテゴリ内の各疾患は、その5種のいずれかを選び、選んだベース種の亜種としてデザインする
- まずカテゴリ全体のベース5種を作って保存し、その後に個別疾患の亜種を作る

例:

- 骨・関節系疾患: 恐竜
- その中のベース種候補:
  - ティラノサウルス
  - トリケラトプス
  - ステゴサウルス
  - ブラキオサウルス
  - プテラノドン

## 制作フロー

1. カテゴリごとのテーマを決める
2. そのカテゴリのベース種を5つ決める
3. 5つすべてのベース種画像を先に作る
4. 各疾患ごとに、その5種のうち最も相性の良いベース種を1つ選ぶ
5. 選んだベース種から、色や形を少しだけ変えた亜種を作る
6. 疾患名とベース種名を掛け合わせてキャラクター名を作る

この順番を固定し、いきなり疾患単体のキャラから作り始めない。

## ベース種の作り方

### 1. 参照画像の扱い

- Wikipedia や図鑑、復元イラスト、骨格図は「参照用」として使う
- 画像をそのまま流用したり、単純トレースしたりしない
- 種の特徴を抽出するために使う

### 2. 抽出すべき特徴

ベース種を作る時は、まず以下を文章で整理する。

- シルエットで何が分かるか
- 頭の形
- 胴体の姿勢
- 四肢の太さと長さ
- 背中や尾の特徴
- 一目でその種と分かる特徴

### 3. ベース画像の役割

ベース画像は「カテゴリ共通の標準体」とする。

- 色は中立的
- 表情は穏やか
- 装飾は控えめ
- まずはシルエット認識を優先

この段階では、疾患固有の差分は入れない。

## 亜種の作り方

各疾患キャラクターは、ベース種の亜種として作る。

### 差分として許容するもの

- 配色
- 模様
- 骨板や翼や角などの一部形状
- 目元や表情のニュアンス
- 小さなアクセント

### 差分として避けるもの

- 疾患症状の直接的な可視化
- 痛みや障害のイメージ化
- 欠損や弱さを想起させる表現
- 病気のつらさを連想させる誇張

## 名前の付け方

- カテゴリテーマ内のベース種名と、疾患名を掛け合わせる
- ただし、意味が伝わらない専門用語だけの名称は避ける
- 語感は覚えやすく、馬鹿に見えないことを優先する

例:

- 低ホスファターゼ症 × ステゴサウルス
  - ホスファテゴサウルス
  - Phosphategosaurus

## ステゴサウルス系ベースの設計方針

骨・関節系疾患カテゴリでは、まずステゴサウルス系を試す。

ベース種として重視する特徴:

- 低く安定した四足歩行
- 小さい頭
- 背中に並ぶ骨板
- 尾のスパイク
- ずんぐりした安心感のある体型

キャラ化の方針:

- 怖さより親しみやすさ
- ただし恐竜としての種の特徴は失わない
- まず「一目でステゴサウルスに見える」ことを優先する

## 実装方針

- ベース種画像は `static/img/characters/base/` に置く
- 疾患ごとの亜種画像は `static/img/characters/` に置く
- キャラ定義は `static/js/utils/disease-characters.js` に持つ
- `summary` と `my-diseases` では、同じ定義を共通利用する
- 疾患キャラクターが未設定の疾患では、`summary` の Hero は 1 カラム表示に戻す
