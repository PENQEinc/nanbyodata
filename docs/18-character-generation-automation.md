# 疾患キャラクター自動化アーキテクチャ

## 目的

疾患キャラクター制作を、少数の手作業ではなく、  
大量の疾患へ段階的に展開できる運用へ移す。

対象は以下を想定する。

- 指定難病
- 小児慢性特定疾病
- 将来的には NANDO 全体の多数疾患

## 前提

完全自動で 3000 疾患を作り切るのではなく、  
まずは **8割自動化 + 2割レビュー** を目指す。

そのために、制作工程を以下に分解する。

1. カテゴリごとの 5 ベース定義
2. 疾患ごとのベース割当
3. 疾患ごとのプロンプト自動生成
4. 画像生成 API または画像生成ツールへの投入
5. 人手による採用判定
6. アプリ用アセットとレジストリ更新

## 構成要素

### 1. ベース定義

ファイル:

- `config/character_bases.json`

役割:

- カテゴリごとのテーマ
- シリーズ基準画像
- 5 ベース種の情報
- 各ベースの画像パス
- 各ベースの識別記号
- 画像生成時の共通ルール

### 2. 疾患割当

ファイル:

- `config/disease_character_map.json`

役割:

- 疾患ID
- 疾患名
- 所属カテゴリ
- 選択するベース種
- キャラクター名
- 出力先ファイル名
- その疾患用の軽い差分ルール

### 3. プロンプト生成

スクリプト:

- `scripts/build_character_prompts.py`

役割:

- `character_bases.json` と `disease_character_map.json` を読み込む
- 疾患ごとの日本語 / 英語プロンプトを組み立てる
- 画像生成やイラスト依頼に直接使える Markdown を出力する

## 基本フロー

### フェーズ 1: ベース種の確定

1. カテゴリごとに 5 ベースを決める
2. 画像生成ツールでベース画像を作る
3. 採用版を `static/img/characters/base/` に配置する
4. docs に採用版を記録する

### フェーズ 2: 疾患ごとの亜種化

1. 疾患ごとにベース種を割り当てる
2. スクリプトでプロンプトを作る
3. ベース画像を見せながら外部の画像生成ツールで亜種画像を生成する
4. 採用画像を `static/img/characters/` に保存する

### フェーズ 3: アプリ組み込み

1. `disease-characters.js` または JSON レジストリを更新する
2. `summary` と `my-diseases` に表示する
3. 必要に応じて docs と採用記録を更新する

## 現在の実証状況

以下の 2 件で、設計からアプリ反映まで一通りのフローを確認済み。

1. `NANDO:1200656` 低ホスファターゼ症
   - ベース: `stegosaurus`
   - キャラクター: `ホスファテゴサウルス / Phosphategosaurus`
2. `NANDO:1200877` 軟骨無形成症
   - ベース: `triceratops`
   - キャラクター: `アコンドロトプス / Achondrotops`

この 2 件では、

- `config/disease_character_map.json` への登録
- `scripts/build_character_prompts.py` によるプロンプト生成
- ベース画像を参照した外部画像生成
- 採用 PNG の配置
- `static/js/utils/disease-characters.js` への登録
- `summary` と `my-diseases` での表示

まで確認できている。

## 推奨ディレクトリ

- ベース画像:
  - `static/img/characters/base/`
- 疾患ごとの採用画像:
  - `static/img/characters/`
- 制作途中の比較用画像:
  - 必要なら別ディレクトリで保持

## 自動化の考え方

### 自動化しやすい部分

- 疾患ごとのベース割当ファイル管理
- プロンプト生成
- ファイル名の統一
- 採用画像の配置先整理
- レジストリ更新の雛形生成

### 人の判断が必要な部分

- ベース種の採用
- 画像の最終採用判定
- 名前のニュアンス
- 不適切な表現の確認

## まず作るもの

この段階では、以下までを整える。

1. 自動化アーキテクチャ文書
2. ベース定義 JSON
3. 疾患割当 JSON
4. プロンプト生成スクリプト

画像生成 API との直接連携は、その次の段階で検討する。  
現状は、生成AI にベース画像と生成プロンプトを渡し、人手で採用判定を行う運用を前提とする。

## 実行例

1件だけ生成する場合:

```bash
python3 scripts/build_character_prompts.py --disease NANDO:1200656
```

すべての設定済み疾患について生成する場合:

```bash
python3 scripts/build_character_prompts.py --all
```

Markdown ファイルとして書き出す場合:

```bash
python3 scripts/build_character_prompts.py --all --out-dir /tmp/character-prompts
```
