# My Disease Feature Specification

## 目的

`summary` ページで見つけた関心疾患を `マイ疾患` として保存し、あとからすぐ再訪できるようにする。  
毎回検索しなくても、自分がよく見る疾患の一覧を NanbyoData 内に持てる状態を目指す。

この機能は、単なるブラウザブックマークではなく、NanbyoData 内で育っていく関心疾患リストとして位置付ける。

## 用語

- `マイ疾患`
  - ユーザーがブラウザ内に保存した関心疾患の一覧
- `登録`
  - 現在表示中の疾患を `マイ疾患` に追加すること
- `解除`
  - `マイ疾患` から対象疾患を外すこと

## 保存方式

- 初期実装では `localStorage` を使う
- ログインは不要
- 保存データはブラウザごとに保持される
- サーバー側の永続化は行わない

`cookie` ではなく `localStorage` を採用する理由:

- 容量に余裕がある
- フロントエンドだけで扱いやすい
- ログイン機能なしで完結できる
- 初期実装として最も軽い

## 保存データ仕様

保存単位は 1 疾患 1 オブジェクトとする。

```json
[
  {
    "id": "NANDO:1200473",
    "label_ja": "非典型溶血性尿毒症症候群",
    "label_en": "Atypical hemolytic uremic syndrome",
    "saved_at": "2026-03-21T10:30:00+09:00"
  }
]
```

### 各項目

- `id`
  - NANDO ID
- `label_ja`
  - 保存時点の日本語疾患名
- `label_en`
  - 保存時点の英語疾患名
- `saved_at`
  - 登録日時

## 現在の実装状態

2026-03-21 時点で、以下は実装済み。

- `summary` ページからの登録 / 解除
- `disease` ページからの登録 / 解除
- グローバルヘッダからの `マイ疾患` 導線
- `/my-diseases` 一覧ページ
- 疾患一覧の制度別タブ表示
- 代表疾患については疾患キャラクター表示

以下は今後の拡張対象。

- ログイン後の端末横断同期
- 比較ページ
- キャラクターの全疾患展開

## 登録 UI

登録 UI は、現在 `summary` ページと `disease` ページの両方に置く。

### 配置

- `summary`
  - 疾患プロフィールパネルの疾患名付近
- `disease`
  - 疾患名ボックス内の NANDO ID 行右端

### 動作

- 未登録時:
  - `マイ疾患に追加`
- 登録済み時:
  - `登録済み`
- クリックでトグル
- 再クリックで解除可能

### UI の方向性

- テキストだけでなく、状態が分かるアイコンを併用する
- `保存` ではなく `マイ疾患` を主語にした文言を使う
- ダウンロードと誤認しないことを優先する
- 未登録と登録済みは、色でも区別できるようにする

## ヘッダ導線

- グローバルヘッダに `マイ疾患` への導線を追加する
- どのページからでも一覧へ行けるようにする
- 初期実装では、登録操作は `summary` ページのみでもよい

## 一覧ページ

`/my-diseases` のような専用ページを作成し、`localStorage` に保存された疾患を一覧表示する。

### 表示内容

- 日本語名
- 英語名
- NANDO ID
- 登録日時
- `summary` ページへのリンク
- `disease` ページへのリンク
- 解除ボタン
- 疾患キャラクター（設定済み疾患のみ）

## 一覧の見せ方

現在は、`マイ疾患` の見出しと一覧を 1 パネルに統合し、その中で

- 制度タブ
- カテゴリ別一覧

を表示する構成を採用している。

### 制度タブ

- `指定難病`
- `小児慢性特定疾病`

の 2 制度を別タブで切り替える。

両方の制度に保存疾患が存在する場合だけタブを表示し、どちらか片方しか無い場合はタブを省略する。

### カテゴリ化ルール

カテゴリは、制度ごとに別のルートを使って決める。

- `指定難病`
  - ルート: `NANDO:1000001`
  - その一つ下の階層をカテゴリとみなす
- `小児慢性特定疾病`
  - ルート: `NANDO:2000001`
  - その一つ下の階層をカテゴリとみなす

各保存疾患について、親をたどって最初に見つかる制度直下カテゴリへ振り分ける。

### 例

- `NANDO:1200719` 一次性ネフローゼ症候群
  - 制度: `指定難病`
  - カテゴリ: `腎・泌尿器系疾患`
- `NANDO:2200053` ユーイング肉腫
  - 制度: `小児慢性特定疾病`
  - カテゴリ: `固形腫瘍（中枢神経系腫瘍を除く。）`

### 一覧の表示イメージ

- `腎・泌尿器系疾患`
  - 疾患カード
  - 疾患カード
- `血液系疾患`
  - 疾患カード
- `神経・筋疾患`
  - 疾患カード

この grouping により、制度が混ざって不自然な並びになるのを防ぎつつ、「関心疾患を集めていく感覚」を出す。

## 初期実装範囲

当初の初期実装範囲は以下だった。

1. `summary` ページに `マイ疾患` 登録ボタンを追加
2. `localStorage` への保存 / 解除
3. ヘッダに `マイ疾患` 導線を追加
4. `マイ疾患` 一覧ページを追加
5. 一覧ページでカテゴリ別に表示

## 実装済み追加事項

- `disease` ページにも登録 UI を追加
- ヘッダの `マイ疾患` ボタンに登録件数を表示
- 一覧ページで制度別タブを追加
- 日本語保存名では ruby のかな部分を除去
- 英語ページでは日本語副題を表示しない
- 一覧カードに `summary` / `detail` / `remove` の操作を統一配置
- 設定済み疾患では疾患キャラクターを表示

## 後続で追加できるもの

- 登録件数表示
- 最近追加した順の並び替え
- 名前順ソート
- カテゴリ別件数
- `マイ疾患` 同士の比較ページ
- ブラウザ間同期

## 補足

- 現在もブラウザローカル保存のみのため、別ブラウザや別端末には引き継がれない
- カテゴリ情報は NANDO OBO をフロントで参照して導出している
- 制度タブとカテゴリ表示は、NANDO ツリー構造に依存する
- 保存データは軽量に保ち、制度カテゴリやキャラクターは表示時に補完する
